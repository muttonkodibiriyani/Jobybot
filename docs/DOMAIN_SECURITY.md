# jobybots.com — security hardening checklist

Run through this once after the domain goes live. Everything is free.

## 1. HTTPS + HSTS (already done in code)
* TLS — auto-provisioned by Vercel (Let's Encrypt).
* HSTS preload — sent on every response by `website/middleware.ts`
  (`max-age=63072000; includeSubDomains; preload`).
* To get on the official **HSTS preload list**, submit
  <https://hstspreload.org/?domain=jobybots.com> after the site has been
  live for a few days. This makes browsers refuse `http://` *before* even
  contacting the server.

## 2. DNS hardening at GoDaddy
Add these records once your basic A / CNAME are in place:

| Type | Name | Value | Purpose |
|---|---|---|---|
| `CAA` | `@` | `0 issue "letsencrypt.org"` | Only Let's Encrypt may issue certs |
| `CAA` | `@` | `0 issue "pki.goog"` | Allow Google Trust Services (Vercel may switch) |
| `CAA` | `@` | `0 iodef "mailto:tharakesh.iitp@gmail.com"` | Get email on rogue cert attempts |

## 3. SPF / DKIM / DMARC (so your transactional emails land in inbox)
You send order confirmations and refund emails from `tharakesh.iitp@gmail.com`.
Because the visible "from" is `tharakesh.iitp@gmail.com` (Gmail-hosted), the
basic SPF/DKIM is already published by Google for `gmail.com`. **No DNS work
is needed for this domain unless you change the From address to
something@jobybots.com.**

If you later switch to a custom sender like `team@jobybots.com`, you'll need:

| Type | Name | Value |
|---|---|---|
| `TXT` | `@` | `v=spf1 include:_spf.google.com ~all` |
| `CNAME` × 3 | `google._domainkey`, etc. | Generated by Gmail when you set up "Send mail as" with custom domain |
| `TXT` | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:tharakesh.iitp@gmail.com; pct=100` |

Until then, leave it — the current setup is the recommended one for a solo
founder.

## 4. WAF — Vercel Firewall (one-click)
Vercel → Project → **Settings → Firewall** → toggle on:
* **Bot Protection** — blocks scraping clients, leaves real browsers
  through.
* **Attack Challenge Mode** — turn ON anytime you're under attack;
  shows a 5-second JS challenge to all visitors.
* **IP Blocking** — add IPs from the `security_events` table when you
  see repeat offenders in the admin dashboard.

## 5. Application-layer protections (already in code)
* **CSP** — `script-src 'self' 'unsafe-inline' https://js.stripe.com` blocks
  any XSS payload from loading external scripts. (`'unsafe-inline'` is
  required for Tailwind / Next inline runtime; we keep `frame-ancestors
  'none'` so the site can never be iframed.)
* **X-Frame-Options: DENY** — clickjacking blocked.
* **X-Content-Type-Options: nosniff** — MIME sniff attacks blocked.
* **Referrer-Policy: strict-origin-when-cross-origin** — outgoing links
  leak only the origin, never the path.
* **Permissions-Policy** — camera/mic/geo/FLoC turned off.
* **Rate limits** — per-IP for `/api/india-order` (6/hr),
  `/api/refund` (4/hr), `/api/admin/login` (5 in 10 min).
* **Security event log** — every limit breach is logged in the
  `security_events` table and surfaced on `/admin`.

## 6. Owner-side hygiene
1. **`ADMIN_PASSWORD`** must be 32+ random characters. Use a password
   manager. Rotate immediately if you receive an alert email.
2. **Gmail App Password** — only used by the website's server. Rotate
   from <https://myaccount.google.com/apppasswords> if Vercel access ever
   leaks.
3. **2FA on:** GitHub, Vercel, GoDaddy, Gmail. Use a hardware key
   (YubiKey, Titan) if possible.
4. **Vercel deploy hooks** — keep them secret. Anyone with the URL can
   trigger a deploy.

## 7. Suspicious-activity alerts (already wired)
The site emails you at `GMAIL_ADDRESS` automatically when any single IP
exceeds the threshold inside 10 minutes:

| Event | Threshold | Action you should take |
|---|---|---|
| `admin_login_failed` | 3 | Rotate `ADMIN_PASSWORD` immediately. |
| `admin_login_rate_limit` | 1 | Same as above. |
| `order_rate_limit` | 5 | Inspect `/admin` security events tab. |
| `refund_rate_limit` | 5 | Probably a bot — block IP in Vercel Firewall. |
| `refund_unknown_order` | 5 | Brute-force ID guesser — block IP. |
| `refund_email_mismatch` | 5 | Account takeover attempt — block IP and rotate. |

## 8. Pen-test the basics before launch
* `https://internet.nl/site/jobybots.com/` — free, comprehensive scan.
  Target: 100% green.
* `https://securityheaders.com/?q=jobybots.com` — should grade **A+**.
* `https://www.ssllabs.com/ssltest/analyze.html?d=jobybots.com` — should
  grade **A** (Vercel ships modern TLS by default).
* `https://hardenize.com/report/jobybots.com` — DNSSEC + DMARC overview.

## 9. Incident response (one-pager)
If you get the alert email or notice anything weird:

1. **Rotate** `ADMIN_PASSWORD` and `GMAIL_APP_PASSWORD` from Vercel env
   vars. Redeploy.
2. **Review** `/admin → Security events` for the offending IP.
3. **Block** the IP under **Vercel → Firewall → IP blocking**.
4. **Snapshot** the orders database (`ORDERS_DB_PATH` or KV) before
   anything else. You need to know what was touched.
5. **Email affected customers** within 72 hours if any PII was likely
   exposed. (GDPR requires this for EU customers.)
